# FXT Team New Tab для Chrome

Версия 1.5.0 открывает https://homepage.fxtteam.ru/ при создании новой вкладки. Расширение проверяет доступность сайта запросом HEAD. При ответах 405 и 501 оно пробует GET. Если сайт недоступен, вкладка показывает часы и кнопку повтора. Строкой поиска управляет сам сайт.

Расширением можно пользоваться сразу после распаковки. Автообновление включается отдельно на каждом компьютере. Оно работает для распакованного расширения через пользовательское задание Windows или таймер systemd в Linux. Ежедневная проверка меняет файлы расширения в постоянной папке. После успешной установки новой версии полностью закройте и снова откройте Chrome или нажмите значок перезагрузки на карточке расширения в `chrome://extensions`.

## Установка расширения

1. На странице [Releases репозитория AenyellHael/browser-startpage-extension](https://github.com/AenyellHael/browser-startpage-extension/releases/latest) скачайте прикреплённый файл **fxtteam-new-tab-v1.5.0.zip** (у следующего выпуска номер будет другим). Для автообновления нужен архив, собранный автором: в его папке `update` лежат `repository.txt` и `allowed_signers`. Архив исходного кода GitHub этих настроек не содержит.
2. Создайте постоянную папку, например `%LOCALAPPDATA%\FXTTeam\NewTab` в Windows или `~/.local/share/fxtteam-new-tab` в Linux. Распакуйте туда архив. Рядом должны лежать `README.md`, папка `extension` с файлом `manifest.json` и папка `update` со скриптами. Используйте отдельную папку для этого расширения: при обновлении каталог `extension` заменяется целиком. Собственные файлы храните отдельно.
3. Перейдите в `chrome://extensions`, включите **Режим разработчика**, нажмите **Загрузить распакованное расширение** и выберите именно папку **extension**. Если Chrome попросит подтвердить замену новой вкладки, подтвердите её.
4. Откройте новую вкладку. Если достаточно ручной установки, на этом всё.

**Переход с 1.4.0 или 1.4.1.** Отключите прежнюю копию в `chrome://extensions`, затем установите новую по инструкции выше. После проверки можно удалить старую карточку. В дальнейшем путь к `extension` должен оставаться постоянным. Для ручного обновления распакуйте содержимое папки `extension` нового выпуска в уже установленную папку и перезагрузите карточку в Chrome.

## Windows — добровольное автообновление

Потребуются Windows PowerShell 5.1, Планировщик заданий и клиент OpenSSH с поддержкой подписей `ssh-keygen -Y verify` (OpenSSH 8.2 или новее). Версию можно посмотреть командой `ssh -V`. Если компонента нет, установите **Клиент OpenSSH** через дополнительные компоненты Windows. Сама задача работает от текущего пользователя с обычными правами. Для установки системного компонента могут потребоваться права администратора.

Откройте обычный Windows PowerShell и перейдите в постоянную папку. Если выбрали другой путь, подставьте его в первую команду. Перед первым запуском проверьте, что `update\repository.txt` содержит ожидаемый репозиторий автора. После проверки источника архива снимите интернет-метку именно с установочного скрипта.

```powershell
Set-Location "$env:LOCALAPPDATA\FXTTeam\NewTab"
Get-Content .\update\repository.txt
Unblock-File -LiteralPath .\update\windows.ps1
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\update\windows.ps1 -Action Enable
```

Команда сразу проверит подписанный релиз. После успешной проверки появится ежедневное задание **FXT Chrome Update** с идентификатором текущего пользователя в имени. Запуск назначен на 12:00 по местному времени. Если компьютер был выключен, планировщик сможет запустить пропущенную задачу позднее, пока пользователь вошёл в систему.

Из той же папки можно проверить состояние, запустить обновление вручную или отключить расписание. Каждая строка — отдельное действие.

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\update\windows.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\update\windows.ps1 -Action Check
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\update\windows.ps1 -Action Disable
```

В выводе **Status** смотрите `NextRunTime` и `LastTaskResult`. После завершённого запуска код 0 означает успех. Для диагностики ошибки запустите **Check** в открытом PowerShell. Политика выполнения в примерах действует только для запущенного процесса и подчиняется политике организации.

## Linux — добровольное автообновление

Потребуются Python 3.8+, `ssh-keygen` из OpenSSH 8.2+ и пользовательский systemd для расписания. Команды запускаются из сеанса обычного пользователя. При отсутствии пользовательского systemd команда `check` доступна для ручной проверки.

```sh
cd "$HOME/.local/share/fxtteam-new-tab"
cat update/repository.txt
python3 update/linux.py enable
```

После проверки подписи первого релиза скрипт создаёт `fxtteam-chrome-update.service` и `fxtteam-chrome-update.timer` в пользовательском каталоге systemd. Таймер запускается ежедневно около 12:00 по местному времени. Благодаря `Persistent=true` пропущенная проверка выполняется после следующего запуска пользовательского таймера.

```sh
# Следующий запуск
python3 update/linux.py status
# Разовая проверка с выводом результата
python3 update/linux.py check
# Журнал заданий, запущенных systemd
journalctl --user -u fxtteam-chrome-update.service -n 30 --no-pager
# Отключить расписание и удалить его пользовательские unit-файлы
python3 update/linux.py disable
```

## Что именно загружается

Каждая проверка получает два небольших файла из последнего стабильного публичного GitHub Release: `chrome-extension.zip` и `chrome-extension.zip.sig`. Скрипт сверяет SSH-подпись с открытым ключом из первоначального установочного архива, проверяет имя расширения и версию в манифесте. Устанавливается только более высокая версия. Пакет подготавливается рядом с текущей папкой, затем занимает её место. Если процесс прервался между переименованиями, повторите **Check**: сначала он восстановит предыдущую папку.

При ошибке сети, несовпадении подписи или отсутствии файлов в Release установленная версия продолжает работать. Повторите проверку позже. Ошибка 404 обычно означает, что в последнем стабильном Release нет обоих вложений или репозиторий закрыт. Для доступа к публичному релизу токен GitHub не нужен.

Автообновление охватывает содержимое `extension`. Для замены скриптов в `update` или смены доверенного ключа автор выпускает новый установочный архив. Проверяйте его источник так же, как при первой установке. Для переноса в другую папку сначала отключите расписание, затем перенесите файлы, заново выберите каталог в Chrome и включите расписание из нового места. Для полного удаления отключите расписание, удалите расширение в Chrome и удалите его постоянную папку.

## Автору — подготовка первой публикации

Скрипт `build_chrome_release.py` находится в корне репозитория рядом с `manifest.json`. Для сборки нужны Python 3.8+ и OpenSSH 8.2+. Команды ниже приведены для Linux, macOS или Ubuntu в WSL; выполните их из корня исходного проекта. В установочный архив автоматически записывается репозиторий `AenyellHael/browser-startpage-extension`. На Windows для запуска Python можно использовать `py -3`.

1. Создайте **отдельный ключ подписи релизов**. Укажите парольную фразу по запросу и сохраните резервную копию ключа. Закрытый ключ хранится вне репозитория. При следующих сборках используйте этот же ключ.

   ```sh
   mkdir -p "$HOME/.ssh"
   ssh-keygen -t ed25519 -f "$HOME/.ssh/fxt-chrome-release" -C "FXT Chrome releases"
   ```

2. Соберите подписанный пакет и установочный архив. Скрипт извлекает открытый ключ, записывает его и имя репозитория в установочный архив. Для результатов сборки используется каталог `dist`.

   ```sh
   python3 build_chrome_release.py \
     --key "$HOME/.ssh/fxt-chrome-release" --out dist
   ```

3. В GitHub откройте **Releases → Draft a new release**, создайте тег (например, `chrome-v1.5.0`) и приложите **все три файла** из `dist`: установочный `fxtteam-new-tab-v1.5.0.zip`, пакет `chrome-extension.zip` и его подпись `chrome-extension.zip.sig`. Опубликуйте выпуск как стабильный **Latest**. Имя версионного архива меняется, имена двух остальных файлов должны оставаться постоянными. Если Chrome и Firefox живут в одном репозитории, последний стабильный выпуск должен всегда содержать актуальную пару файлов Chrome.
4. Для следующей версии увеличьте `version` в корневом `manifest.json`, повторите сборку и опубликуйте новый Latest Release с тремя вложениями. После публикации выполните **Check** на тестовой установке прежней версии. Перезагрузите расширение и сверьте номер на карточке в `chrome://extensions`.

До первой публикации для ручной установки из исходников выберите в Chrome корень репозитория, где находится `manifest.json`. Для включения расписания используйте собранный установочный архив и доступный подписанный Release.
